# Backend

FastAPI API, CSV replay, TCP NDTP, состояние ТС и вызов отдельного ML-сервиса.
Признаки импортируются из `transport_ml`; модели не обучаются в запросе.

Из корня проекта после установки зависимостей:

```bash
BACKEND_ML_URL=http://127.0.0.1:8011 .venv/bin/transport-backend serve --port 8010
.venv/bin/python -m pytest -q backend/tests
```

Полный запуск: `docker compose up --build`. Контракт и endpoints —
[API_CONTRACT](../docs/API_CONTRACT.md), сценарии — [DEMO](../docs/DEMO.md).

`BACKEND_MODE=replay` использует исторические прогнозные точки; `ndtp` по умолчанию
выбирает цели только из плана, подсказку оценивает по GPS либо использует fallback.
`BACKEND_USE_POINTS=true` явно включает офлайн-точки для диагностического прогона.
Для NDTP нужен явный unit→tr mapping из загруженного traffic CSV и подходящий план.
Отсутствующие сведения не восстанавливаются по скрытой разметке.

Первое время известного устройства принимается только внутри диапазона плана
± окна истории. Затем отклоняется скачок более 60 с вперёд относительно часов
источника; неизвестные устройства часы не меняют. Это демонстрационная политика:
ошибочную первую метку внутри диапазона плана она выявить не может.
Поздние пакеты сохраняются по event-time; последняя валидная позиция не регрессирует.
История ограничена окном и количеством событий; недавние неизвестные unit ограничены 256,
NDTP-счётчики по unit — 1024. Длительный нагрузочный тест ещё требуется.

Текущее отклонение (`VehicleView.current_deviation`) публикуется независимо от ML:
общий GPS/plan estimator, отдельный кеш в цикле Backend, HTTP не запускает мэтчинг.
Возраст оценки ограничен `BACKEND_CURRENT_DEVIATION_MAX_AGE_S` (300 с по умолчанию),
возраст GPS — `BACKEND_STALE_AFTER_S`; исторические значения остаются с status stale.
При reset/seek кеш сбрасывается/восстанавливается причинно. ML features не менялись.

## Локальная панель демо

`BACKEND_DEMO_ENABLED=true` включает `GET /api/v1/demo/sources` и
`POST /api/v1/demo/source`: источники replay / ndtp_replay / emulator.
Контроллер владеет sender и движком; смена источника закрывает старые TCP-соединения
и очищает состояние. Наш sender использует настоящий loopback TCP; официальный
эмулятор управляется HTTP и должен быть заранее запущен профилем Compose.
`BACKEND_EMULATOR_URL` — фиксированный URL, `BACKEND_EMULATOR_TARGET_HOST` — адрес
Backend, видимый контейнеру эмулятора. Без Compose панель по умолчанию отключена.
Не запускать внешние отправители параллельно с панелью. Семантика ошибок и fallback —
[API_CONTRACT](../docs/API_CONTRACT.md#11-панель-демо-и-переключение-источников).

## История просмотра NDTP

`ViewHistory` сохраняет согласованные снимки и карточки после цикла обработки,
по времени публикации. `GET /api/v1/history?run_id=…&at=…` читает предыдущую запись
без вмешательства в часы/ML. Журнал общий для всех NDTP-источников, курсор локален
браузеру. Сжатые неизменяемые записи ограничены временем, количеством и байтами;
параметры `BACKEND_VIEW_HISTORY_*` описаны в `.env.example`. По умолчанию до 2 часов
времени источника, 7200 записей, 64 МиБ. Новый прогон/рестарт очищает память.
Это отдельное хранилище представлений UI; оно не расширяет окно признаков ML.
Контракт, разреженность записей и поведение при регрессии часов —
[API_CONTRACT, раздел 12](../docs/API_CONTRACT.md#12-журнал-просмотра-ndtp-совместимое-дополнение-v1).
