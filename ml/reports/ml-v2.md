# Отчёт ML v2: вероятность опоздания поверх неизменной регрессии

Дата: 26.09.2026. Артефакт: `ml/pretrained/v2` (копия запуска `artifacts/ml-v2`).
Команда: `python -m transport_ml train --model artifacts/ml-v2`, затем `predict`.
Конфигурация: seed 42, iterations 600, learning rate 0,05, development 25%,
порог опоздания 120 с (совпадает с `target_class`).

## 1. Что изменилось относительно v1

Регрессия, признаки (44, schema 1), split и границы окна не менялись. Проверка: test MAE
`79,0874 с`, fallback `87,3271 с`, `submission.csv` побайтово равен v1. Добавлены
`late.cbm` и `late_fallback.cbm` плюс Platt-калибровка и метрики надёжности.

| Предиктор | MAE test, с |
|---|---:|
| Нулевой прогноз | 103,3371 |
| Медиана real train | 101,2011 |
| Подсказка `cur_dev_s` | 93,3598 |
| Обученный fallback без подсказки | 87,3271 |
| Основная модель | **79,0874** |

## 2. Протокол вероятности

1. Метка: `target_delay_s > 120 с`. Доля опозданий в обучающих real-строках — 0,2103.
2. Деревья растут **только** на fit-фолде (844 строки), early stopping по development.
3. Выбор глубины — по Brier на development: `late` depth 4 / 187 деревьев,
   `late_fallback` depth 6 / 41 дерево.
4. Platt `p = σ(a·score + b)` подобран на development (287 строк, 76 опозданий) со
   сглаженными целями. Классификатор **не** дообучается на всех строках: иначе
   калибровка перестала бы соответствовать своим же скорам.
5. Test используется только для отчёта ниже, уже после фиксации моделей и калибровки.

## 4. Ограничения

- Калибровка подобрана на development того же дня; статус в manifest —
  `fitted_on_development`. Это не проверка на независимом дне и не гарантия переноса.
- Бин 0,4–0,6 переоценивает риск (0,489 против 0,333 на 66 строках); середина шкалы
  наименее надёжна. Продуктовые пороги должны это учитывать.
- Без подсказки вероятность заметно слабее (AUC 0,6935): выигрыш над базовой частотой
  маленький, поэтому в UI режим fallback помечается отдельно.
- Test делит день и ТС с train и телеметрию с validate; это локальный benchmark.
- Групповой holdout по ТС (ML-02) по-прежнему не выполнен.
