# ML-02: проверка на отложенных реальных ТС

26.09.2026. На выбранном групповом holdout обученная модель **уступает подсказке**:
MAE 99,0957 с против 91,6494 с. Преимущество на обычном test не подтверждается
на этих отложенных ТС. Готовые v1/v2 и submission не менялись; эксперимент не принят
как замена модели. Подбор параметров после просмотра holdout не проводился.

## Протокол

Вход — только `dataset/train/{traffic,schedule}.csv` и `labels/labels_train.csv`.
Из 4 434 точек исключены 3 293 синтетические (`tr_id >= 9000000`), поскольку их
семейства неизвестны. Использован общий FeatureBuilder, schema 1, 44 признака.
Фактическое расписание исключено allowlist загрузчика; события обрезаются по T.
Test и validate команда не читает, готовые модели не использует.

Внешний split не зависит от labels: уникальные строковые ID сортируются,
перемешиваются `numpy.random.default_rng(42)`, первые `ceil(13 × 0,25) = 4` ТС
уходят в holdout **целиком**. Split записывается до обучения.

Внутренняя временная граница по оставшимся ТС — `2026-01-06 16:15:00`.

(включая внутренние development/purge). Внешние holdout-строки не участвуют ни в
подборе, ни в early stopping, ни в refit, ни в расчёте train-медианы.

Выбраны main direct depth 4 / 22 дерева и fallback depth 4 / 47 деревьев.
Это проверка процедуры обучения на меньшем train, а не оценка готовой v1/v2:
готовые модели уже видели labels этих ТС и для такого эксперимента непригодны.

## Воспроизведение и происхождение

Из корня проекта, каждый раз с новым каталогом:

```bash
.venv/bin/python -m transport_ml validate-groups \
  --output artifacts/ml-02-new-run --seed 42 --holdout-fraction 0.25
```

Каталог содержит модели, manifest, metrics, split и holdout predictions. Существующий
каталог не перезаписывается. В Git сохранены небольшие доказательства:
[manifest](ml-02-group-holdout-manifest.json), [metrics](ml-02-group-holdout-metrics.json),
[точный split](ml-02-group-holdout-split.csv). Модели остаются в `artifacts/`.

Исходный запуск: `artifacts/ml-02-group-holdout-20260926`; повторный:
`artifacts/ml-02-group-holdout-reproduce-20260926`. Split и predictions побайтово
совпали, метрики совпали без учёта времени выполнения. Base commit:
`93c0464c3af72ae98caad0c080be439b44cf415e`; запуск использовал незакоммиченный код,
его точные SHA-256, версии окружения и SHA-256 данных сохранены в manifest.

Проверки: 66 pytest-тестов, Ruff check/format; новый тест меняет labels, признаки и
времена holdout и проверяет неизменность выбранных моделей и их предсказаний.
Inference v1 дал 151 прогноз, побайтово совпавший с зафиксированным submission.

## Ограничения и следующий шаг

- Это один seed и четыре ТС одного дня, а не новый день и не доверительный интервал.
- Признаки и кандидаты были разработаны до выделения этих групп; результат не является
  полностью слепой оценкой всей истории разработки.
- Доля ТС 25% дала 42,2% строк: группы разного размера. Оценка взвешена по строкам.
- Синтетика и вероятность опоздания здесь не оценивались. Калибровка v2 сохраняет
  прежнее ограничение `fitted_on_development`.
- Следующий ML-шаг — заранее зафиксировать более широкий групповой протокол перед
  новыми абляциями; не выбирать следующий seed ради лучшего числа. Для поставки
  приоритетна проверка уже существующего сквозного Docker-контура.
