# ML v4/v5: вся честная разметка, объяснимый прогноз и проверенная вероятность

27.09.2026. Модель по умолчанию — **v5**. После публикации v4 пользователь сообщил
**score 0,86126** против прежних 0,70106; точный загруженный файл/hash не подтверждён
(запись ML-V5-20). Регрессоры и CSV v4/v5 побайтово совпадают. Классификатор опоздания
v5 заменил классификатор v2: Brier без подсказки 0,1763 → 0,1162, ROC-AUC 0,694 → 0,878.
Каждый прогноз теперь раскладывается на вклады групп признаков в секундах.

## 1. Границы честности (проверено до экспериментов)

Train, test и validate — один день 2026-01-06 и одни и те же 13 реальных ТС; целевые
посещения не пересекаются. Поэтому важно, что из данных **не** используется:

| Источник | Что обнаружено | Решение |
|---|---|---|
| `time_fact_begin` в train/test schedule | Факты прибытия для **всех 151** целевых посещений validate | Никогда не читается кодом признаков и обучения |
| Синтетические ТС train (26 шт.) | Копия дня реального ТС (по 2 на каждый), сдвиг 1–34 мин, те же остановки, задержки = оригинал ± ~20 с (corr 0,95–0,99), на validate-посещениях отличие 5–26 с | Исключены: с координатами остановки это перенос ответов validate |
| Test labels (353) | Цели не пересекаются с validate; README: «на них вы обучаете и проверяете» | Используются в итоговой модели после отдельной проверки пользы |

Признаки строятся только из событий `event_time <= T` и **планового** расписания; модель
одинаково работает на CSV и на потоке NDTP (общая функция признаков, отдельный ML-сервис).

## 2. Регрессия v4: тот же рецепт, больше данных

Рецепт v3 (шесть CatBoost MAE, 73 признака schema 2) заморожен. Две проверки до обучения:

- кривая обучения на train: MAE 79,51 / 78,55 / 77,34 / 75,98 с при 50 / 65 / 80 / 100%
  данных — плато не достигнуто;
- 5 частей test, каждая предсказана рецептом на train и на train + остальные части:

| Отложено | С подсказкой | Без подсказки |
|---|---:|---:|
| Точки вперемешку (как validate) | 70,67 → **67,87** | 83,27 → **80,12** |
| Целые ТС | 70,67 → **69,60** | 83,27 → **81,89** |

Улучшение во всех четырёх постановках. В групповой проверке исключены test-строки
отложенных ТС, но их train-строки остаются: это не проверка на полностью новых ТС. v4 обучена на
1494 точках (1141 train + 353 test); повторное обучение даёт побайтово тот же CSV.

Отклонённые идеи (критерий CV протокола v3, база 75,98 с): физические признаки ETA 76,41;
усреднение seed 76,13; смесь 0,8·main + 0,2·fallback 75,54 на CV и 72,86 против 74,37 на
outer, но хуже на test (71,74 → 72,12, bootstrap [−1,76; +0,80]) — не внедрена.
Очистка подменённого GPS в признаках: подмена затрагивает 11/151 validate-точек с малой
задержкой, выигрыш не ожидается; фильтр применён только к карте.

## 3. Вероятность опоздания v5

`P(задержка > 120 с)`: CatBoost Logloss на 73 признаках, глубина 4, 300 деревьев — рецепт
зафиксирован до проверки. Калибровка Platt на пятифолдовых out-of-fold оценках строк
обучения. Проверка вне фолдов на тех же 5 частях test (классификатор v2 test не видел):

| Режим | Brier v2 → v5 | Log loss v2 → v5 | ROC-AUC v2 → v5 |
|---|---:|---:|---:|
| С подсказкой | 0,1395 → **0,1065** | 0,428 → **0,339** | 0,818 → **0,895** |
| Без подсказки (поток) | 0,1763 → **0,1162** | 0,525 → **0,367** | 0,694 → **0,878** |

Brier базовой частоты 0,1843. Надёжность по корзинам: предсказано 0,07 / 0,27 / 0,49 /
0,69 / 0,89 при наблюдаемых 0,05 / 0,31 / 0,55 / 0,63 / 0,95 (с подсказкой).

## 4. Объяснение каждого прогноза

ML-сервис возвращает `explanation`: SHAP-вклады CatBoost, взвешенные по ансамблю и сгруппированные
(подсказка, положение относительно расписания по GPS, стоянки, скорость, путь до цели,
время и место, свежесть телеметрии). Для основной модели
`delay = cur_dev + базовая поправка + Σ вкладов`, для автономной — без `cur_dev`. Сумма
совпадает с прогнозом (тест, погрешность ≤ 0,01 с). Стоимость ~1,5 мс на прогноз; объяснение
запрашивается через `explain=true` (по умолчанию выключено). Это арифметика модели, а не установленная причина.

## 5. Ограничения

- Один день и 13 реальных ТС; перенос на другой день не доказан.
- Test вошёл в обучение итоговых моделей: прямой test-скор не публикуется, в
  `metrics.json` — только оценки вне фолдов; replay-MAE дашборда на test помечен in-sample.
- В потоке без supplied `cur_dev_s` работает автономная модель (оценка 80,12 с против 67,87).
- Абсолютные координаты и время суток среди признаков помогают внутри одного дня; на новом
  дне их польза может быть меньше.
