manifest v5. Временный стенд удалён после проверки; основной оставлен работающим.
[Машинный протокол](delivery-29-verification.json).

Дополнительно: **191 pytest passed**, Ruff ML/Backend, TypeScript/Vite, Sphinx с `-W`;
OpenAPI JSON в документации совпали с ответами работающих сервисов; CSV v5 воспроизведён
побайтово. Это короткая проверка интеграции, не новый latency/throughput/soak benchmark.
Официальный эмулятор и браузерные сценарии отказов в этой проверке не повторялись.
Карта основного стенда загружается; в клоне ключ карты намеренно отсутствует.


## Замер v5 в Docker: NDTP и отказ ML (27.09.2026)

Ветка `claude/jolly-noether-9yp4y4` (`aeee188`), модель v5 (manifest `03760ad9…`), Linux x86_64,
Docker 29.3.1. Замер автора ветки, теперь объединённой в `main` (`6b33e7a`).
`git clone` → адаптация сборочной среды → `docker compose up -d --build --wait`: ML, Backend и UI
**healthy за 1 мин 38 с** (базовые образы уже скачаны). В песочнице сборки egress-прокси
пропускает только HTTPS и блокирует deb.debian.org, поэтому в копии клона добавлены CA прокси
и `libgomp` с хоста вместо `apt-get`; Dockerfile репозитория не изменены. На обычной машине
это не требуется. Замер не подтверждает cold start неизменённого репозитория без cache.
CPU/RAM машины и точная частота принятых кадров в протоколе не сохранены.

Источник — `ndtp_replay` (исторический CSV → настоящие NDTP-кадры по TCP, 60×), прогноз
каждые 30 с источника, tick 0,5 с. [Сырой ответ `/api/v1/status`](performance-v5-sample.json).

Память после 29 532 NDTP-кадров: Backend 137 МиБ, ML 84 МиБ, UI 5 МиБ. NDTP: 0 ошибок CRC,
0 битых кадров, 8 обрывов соединения — все переподключения приняты. Фильтр подмены GPS
скрыл 2 466 фиксов. Событие → публикация включает ожидание tick (до 500 мс) и расчёт 73
признаков; это не время отрисовки в браузере (polling 1 с).

Стабильность памяти: при росте числа NDTP-кадров с 29 532 до 56 324 Backend 137 → 139 МиБ,
ML 84 → 85,5 МиБ, UI ~5 МиБ — на этом интервале большой рост не наблюдался (окно состояния ограничено
30 мин и 900 событиями на ТС). Это ~30 минут работы, не многочасовой прогон и не доказательство отсутствия утечек.
Значения памяти, второй счётчик кадров и 1:38 сохранены в журнале автора BASE-21/22;
отдельных сырых docker stats/таймингов в Git нет. JSON выше содержит 29 532 кадра,
30 подключений/handshake, 8 disconnects, 6 read timeouts и 3 ошибки ML (0 таймаутов ML).
Причины всех этих ошибок по одному снимку установить нельзя. Отсутствие накопления
очередей и предельный throughput отдельно не измерялись.

Отказ ML: `docker compose stop ml` — Backend отвечает 200, `ml.ready=false`, прогнозы
получают статус `ml_unavailable` с последним числом и реальным возрастом (63 с в замере);
`docker compose start ml` — прогнозы `ok` возвращаются без перезапуска Backend.

До переноса SHAP-объяснений из цикла на запрос инференс был 56/99 мс (p50/p95).
