60×, интервал расчёта 30 с источника, tick 0,5 с wall-clock. Снимок получен
через `GET http://localhost:8010/api/v1/status` в 15:22:18 UTC.
[Сырой ответ](performance-live01-sample.json) сохранён для проверки чисел.
Параллельно выполнялся короткий NDTP smoke на том же ML: результаты зависят от
локальной нагрузки и не являются сравнением производительности версий.

| Измерение | Samples | p50, мс | p95, мс |
|---|---:|---:|---:|
| ML inference | 348 | 3,71 | 6,36 |
| Backend → ML → Backend | 348 | 7,48 | 11,66 |
| FeatureBuilder | 349 | 36,36 | 46,28 |
| Цикл Backend | 349 | 50,60 | 65,70 |
| Использованное событие → публикация прогноза | 512 | 51,00 | 79,32 |

Последняя строка — по времени приёма события, зафиксированному до ML await;
скользящее окно хранит до 512 samples. Это не сетевое время от устройства и не
задержка до отрисовки браузера (polling добавляет до своего интервала).
Прогнозы для cutoff раньше последнего принятого события не включаются в эту
метрику, поскольку точное время приёма их префикса отдельно не хранится.
В снимке 2161 прогноз, 0 ошибок/таймаутов ML; это не оценка максимального throughput.
