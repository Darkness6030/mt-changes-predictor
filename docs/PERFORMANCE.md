# Условия и результаты замеров

Основные результаты относятся к текущей **v8**. Сохранённые замеры v5 и v3
оставлены в архивном разделе ниже. Краткий текст для сдачи: [FEATURES.md](../FEATURES.md).

## v8: скорость инференса

Linux x86_64 (`Linux-6.18.44-fc-v37-x86_64-with-glibc2.39`),
300 повторов после прогрева для каждого размера пакета. ONNX Runtime использует
один поток на сессию; вызовы CatBoost оставлены с настройками по умолчанию. Измерялся
`DelayModel.infer`: задержка и вероятность на готовых признаках validate.
Подготовка признаков, HTTP, SHAP и экспорт при старте в замер не входят.
Модель CPU и объём RAM в протоколе не указаны.

V8 содержит два ансамбля по шесть регрессоров, гейт нулевой задержки
и два классификатора опоздания. Конкретный набор выбирается по наличию подсказки.
В режиме ONNX нулевой гейт по-прежнему вычисляется CatBoost; его время входит в замер.

| Число прогнозов | CatBoost p50 / p95, мс | ONNX p50 / p95, мс | Ускорение p50 |
|---:|---:|---:|---:|
| 1 | 19,65 / 28,02 | 6,15 / 7,13 | 3,20× |
| 8 | 19,41 / 28,88 | 7,99 / 10,20 | 2,43× |
| 32 | 20,07 / 30,78 | 11,10 / 13,75 | 1,81× |
| 128 | 20,51 / 30,77 | 22,33 / 27,87 | 0,92× |

Для пакета из 128 прогнозов медиана ONNX выше, хотя p95 ниже. Ускорение
на одном прогнозе нельзя переносить на любой размер пакета или всю систему.

На всех 151 validate-точке максимальное расхождение ONNX и CatBoost составило
0,00009078 с с подсказкой и 0,00006983 с без неё. Расхождение вероятности
не превышает 2,98×10⁻⁷. Это сравнение движков, без скрытых ответов validate.

[Исходный JSON](../ml/experiments/onnx-benchmark-v8.json).
Повтор из окружения, установленного по [README](../README.md):

```bash
.venv/bin/python ml/experiments/onnx_benchmark.py artifacts/onnx-v8-repeat.json ml/pretrained/v8
```

Выберите новый путь результата. Без второго аргумента скрипт проверяет v5.
Машины в замерах v5 и v8 различаются, поэтому их абсолютные времена нельзя
использовать для сравнения скорости версий модели.

## v8: CSV replay и сданный файл

Backend последовательно обработал день validate с заданными forecast points
и supplied-подсказкой `cur_dev_s`. Его опубликованные прогнозы сравнили
с [submission.csv](../ml/pretrained/v8/submission.csv). Это CSV replay через
ML-сервис, не проверка TCP-доставки NDTP и не автономный режим без подсказки.

| Проверка | Результат |
|---|---:|
| Прогнозные точки, доставленные Backend | 151 из 151 |
| Точки с числовым прогнозом | 139 |
| Отличие от CSV меньше 0,01 с | 138 из 139 |
| Максимальное отличие | 0,023182 с |
| Медианное отличие | 0,00000775 с |
| Точки со статусом `stale` | 12 |

Во всех 12 случаях возраст последней достоверной GPS-позиции превышал порог
120 секунд: терминалы передавали `location_valid=false`. Поток не публиковал
число, а offline CSV содержал прогноз. Поэтому весь поток не идентичен CSV,
хотя доступные числовые результаты близки.

[Протокол](stream-csv-parity.json) содержит версию модели, ID точек, статусы
и возраст последней достоверной позиции. [Скрипт сравнения](../ml/experiments/stream_csv_parity.py)
описывает запуск validate replay и команду проверки. Скрытая разметка validate
не используется; это проверка согласованности, а не MAE модели.

## Что ещё не измерено для v8

В этих двух протоколах нет полной задержки от получения NDTP до браузера,
предельной пропускной способности, многочасовой нагрузки и холодного старта
без кеша. Они не заменяют такие проверки. Score платформы **0,95394**
зафиксирован отдельно в [описании v8](../ml/pretrained/v8/README.md).

## v5: CatBoost и ONNX Runtime

Linux x86_64, ONNX Runtime CPU, один поток, модель v5. Измерялся
`DelayModel.infer`: задержка и вероятность на готовых признаках, без HTTP,
подготовки признаков, SHAP и стартового экспорта. После одного прогрева выполнено
300 повторов для каждого размера пакета.

| Число прогнозов | CatBoost p50 / p95, мс | ONNX p50 / p95, мс |
|---:|---:|---:|
| 1 | 8,87 / 12,71 | 1,85 / 3,26 |
| 8 | 9,10 / 12,42 | 2,68 / 4,04 |
| 32 | 8,66 / 11,99 | 3,11 / 3,69 |
| 128 | 8,60 / 10,90 | 6,27 / 7,51 |

На 151 validate-точке максимальное расхождение составило 0,00008014 с
для задержки и 2,98×10⁻⁷ для вероятности. Это сравнение двух движков, без скрытых ответов validate.
Модель CPU и объём памяти хоста не записаны.

[Исходные результаты](../ml/experiments/onnx-benchmark.json).
[Скрипт замера](../ml/experiments/onnx_benchmark.py).
Повтор из окружения, установленного по [README](../README.md):

```bash
.venv/bin/python ml/experiments/onnx_benchmark.py artifacts/onnx-repeat.json
```

Скрипт использует v5; для нового запуска выберите новый путь результата.
Compose запрашивает ONNX, а стартовая проверка сравнивает задержку с CatBoost
на 64 синтетических строках. При расхождении больше 0,001 с или ошибке остаётся
CatBoost. Выбранный движок виден в `/v1/model`.

Повтор на macOS arm64 подтвердил численное совпадение; для пакета из 128 строк
p95 ONNX оказался выше CatBoost. Ускорение зависит от размера пакета и нагрузки.
[Протокол повтора](onnx-30-verification.json).

## v5: NDTP → Backend → ML

Docker 29.3.1, Linux x86_64, v5/CatBoost. Исторические данные передавались
бинарными NDTP-кадрами на скорости 60×. Прогноз рассчитывался каждые 30 секунд времени
источника с тактом Backend 0,5 секунды. В таблице по 512 измерений.

| Этап | p50, мс | p95, мс |
|---|---:|---:|
| ML-инференс | 8,92 | 14,35 |
| HTTP Backend → ML → Backend | 15,21 | 22,77 |
| Подготовка признаков | 42,26 | 65,02 |
| Цикл Backend | 95,75 | 149,46 |
| Приём события → публикация прогноза | 172,32 | 316,50 |

Последняя строка включает ожидание такта Backend, но не доставку от устройства
и не отрисовку UI. Дашборд опрашивает API раз в секунду.

В [снимке состояния](performance-v5-sample.json) записаны 29 532 кадра, 30 подключений,
8 закрытий соединений, ноль ошибок CRC и повреждённых кадров. Проверено
восстановление после разрыва TCP и остановки/запуска ML. Это демонстрационный
прогон; частота входящих кадров, характеристики CPU и RAM хоста не зафиксированы.

## v5: воспроизводимость запуска

27.09.2026 проверен отдельный чистый клон v5 на macOS arm64, Docker Engine 29.5.2,
Linux aarch64: три healthy-сервиса без `.env` и изменений Dockerfile.
Использовался кеш образов. В NDTP-проверке принято 6707 кадров без ошибок
CRC, некорректных и обрезанных кадров; прогнозы попадали в горизонт `(600, 900]`.
[Протокол](delivery-29-verification.json).

Это проверка запуска, а не холодного старта без кеша. Предельная пропускная
способность, многочасовая нагрузка и задержка до браузера отдельно не измерялись.
