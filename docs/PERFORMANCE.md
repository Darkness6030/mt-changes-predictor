# Производительность и надёжность

## Замер v5 в Docker: чистый клон, NDTP, отказ ML (27.09.2026)

Ветка `claude/jolly-noether-9yp4y4` (`aeee188`), модель v5 (manifest `03760ad9…`), Linux x86_64,
Docker 29.3.1. Чистый `git clone` → `docker compose up -d --build --wait`: ML, Backend и UI
**healthy за 1 мин 38 с** (базовые образы уже скачаны). В песочнице сборки egress-прокси
пропускает только HTTPS и блокирует deb.debian.org, поэтому в копии клона добавлены CA прокси
и `libgomp` с хоста вместо `apt-get`; Dockerfile репозитория не изменены. На обычной машине
это не требуется.

Источник — `ndtp_replay` (исторический CSV → настоящие NDTP-кадры по TCP, 60×), прогноз
каждые 30 с источника, tick 0,5 с. [Сырой ответ `/api/v1/status`](performance-v5-sample.json).

| Измерение | Samples | p50, мс | p95, мс |
|---|---:|---:|---:|
| ML inference (без объяснений) | 512 | 8,92 | 14,35 |
| Backend → ML → Backend | 512 | 15,21 | 22,77 |
| FeatureBuilder (73 признака, schema 2) | 512 | 42,26 | 65,02 |
| Цикл Backend | 512 | 95,75 | 149,46 |
| Событие → публикация прогноза | 512 | 172,32 | 316,50 |

Память после 29 532 NDTP-кадров: Backend 137 МиБ, ML 84 МиБ, UI 5 МиБ. NDTP: 0 ошибок CRC,
0 битых кадров, 8 обрывов соединения — все переподключения приняты. Фильтр подмены GPS
скрыл 2 466 фиксов. Событие → публикация включает ожидание tick (до 500 мс) и расчёт 73
признаков; это не время отрисовки в браузере (polling 1 с).

Отказ ML: `docker compose stop ml` — Backend отвечает 200, `ml.ready=false`, прогнозы
получают статус `ml_unavailable` с последним числом и реальным возрастом (63 с в замере);
`docker compose start ml` — прогнозы `ok` возвращаются без перезапуска Backend.

До переноса SHAP-объяснений из цикла на запрос инференс был 56/99 мс (p50/p95).

## Короткий замер, не нагрузочная сертификация

`docker compose up -d --build --wait`, режим replay/test, начало 08:00,
60×, интервал расчёта 30 с источника, tick 0,5 с wall-clock. Снимок получен
через `GET http://localhost:8010/api/v1/status` в 15:22:18 UTC.
[Сырой ответ](performance-live01-sample.json) сохранён для проверки чисел.
Параллельно выполнялся короткий NDTP smoke на том же ML: результаты зависят от
локальной нагрузки и не являются сравнением производительности версий.

| Измерение | Samples | p50, мс | p95, мс |
|---|---:|---:|---:|
| ML inference | 348 | 3,71 | 6,36 |
| Backend → ML → Backend | 348 | 7,48 | 11,66 |
| FeatureBuilder | 349 | 36,36 | 46,28 |
| Цикл Backend | 349 | 50,60 | 65,70 |
| Использованное событие → публикация прогноза | 512 | 51,00 | 79,32 |

Последняя строка — по времени приёма события, зафиксированному до ML await;
скользящее окно хранит до 512 samples. Это не сетевое время от устройства и не
задержка до отрисовки браузера (polling добавляет до своего интервала).
Прогнозы для cutoff раньше последнего принятого события не включаются в эту
метрику, поскольку точное время приёма их префикса отдельно не хранится.
В снимке 2161 прогноз, 0 ошибок/таймаутов ML; это не оценка максимального throughput.
