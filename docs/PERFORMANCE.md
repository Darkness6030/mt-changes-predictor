# Условия и результаты замеров

Текущая поставка использует **v8**: ниже её замер инференса и проверка потока против CSV.
Остальные разделы относятся к **v5** и отдельно указанной исторической v3.
Краткий текст для сдачи: [FEATURES.md](../FEATURES.md).

## v8: инференс и совпадение потока с CSV

Linux x86_64, один поток, 300 повторов `DelayModel.infer` (задержка и вероятность) на готовых
признаках validate. В v8 12 регрессоров, гейт нулевой задержки и 2 классификатора.

| Число прогнозов | CatBoost p50 / p95, мс | ONNX p50 / p95, мс |
|---:|---:|---:|
| 1 | 19,65 / 28,02 | 6,15 / 7,13 |
| 8 | 19,41 / 28,88 | 7,99 / 10,20 |
| 32 | 20,07 / 30,78 | 11,10 / 13,75 |
| 128 | 20,51 / 30,77 | 22,33 / 27,87 |

Расхождение ONNX и CatBoost: до 9,1×10⁻⁵ с для задержки, до 3×10⁻⁷ для вероятности.
Машина не та, что в замере v5 ниже, поэтому абсолютные числа напрямую не сравниваются.
[Результаты](../ml/experiments/onnx-benchmark-v8.json); повтор:
`.venv/bin/python ml/experiments/onnx_benchmark.py artifacts/onnx-v8.json ml/pretrained/v8`.

Поток против CSV: Backend воспроизвёл день validate через тот же ML-сервис v8 и выдал
139 числовых прогнозов — все совпали с `submission.csv` (максимум 0,023 с). Ещё 12 точек
получили статус «данные устарели»: терминал передавал `location_valid=false`.
[Протокол](stream-csv-parity.json), [скрипт](../ml/experiments/stream_csv_parity.py).

## Инференс: CatBoost и ONNX Runtime

Linux x86_64, ONNX Runtime CPU, один поток, модель v5. Измерялся
`DelayModel.infer`: задержка и вероятность на готовых признаках, без HTTP,
подготовки признаков, SHAP и стартового экспорта. После одного прогрева выполнено
300 повторов для каждого размера пакета.

| Число прогнозов | CatBoost p50 / p95, мс | ONNX p50 / p95, мс |
|---:|---:|---:|
| 1 | 8,87 / 12,71 | 1,85 / 3,26 |
| 8 | 9,10 / 12,42 | 2,68 / 4,04 |
| 32 | 8,66 / 11,99 | 3,11 / 3,69 |
| 128 | 8,60 / 10,90 | 6,27 / 7,51 |

На 151 validate-точке максимальное расхождение составило 0,00008014 с
для задержки и 2,98×10⁻⁷ для вероятности. Это сравнение двух движков, без скрытых ответов validate.
Модель CPU и объём памяти хоста не записаны.

[Исходные результаты](../ml/experiments/onnx-benchmark.json).
[Скрипт замера](../ml/experiments/onnx_benchmark.py).
Повтор из окружения, установленного по [README](../README.md):

```bash
.venv/bin/python ml/experiments/onnx_benchmark.py artifacts/onnx-repeat.json
```

Скрипт использует v5; для нового запуска выберите новый путь результата.
Compose запрашивает ONNX, а стартовая проверка сравнивает задержку с CatBoost
на 64 синтетических строках. При расхождении больше 0,001 с или ошибке остаётся
CatBoost. Выбранный движок виден в `/v1/model`.

Повтор на macOS arm64 подтвердил численное совпадение; для пакета из 128 строк
p95 ONNX оказался выше CatBoost. Ускорение зависит от размера пакета и нагрузки.
[Протокол повтора](onnx-30-verification.json).

## NDTP → Backend → ML

Docker 29.3.1, Linux x86_64, v5/CatBoost. Исторические данные передавались
бинарными NDTP-кадрами на скорости 60×. Прогноз рассчитывался каждые 30 секунд времени
источника с тактом Backend 0,5 секунды. В таблице по 512 измерений.

| Этап | p50, мс | p95, мс |
|---|---:|---:|
| ML-инференс | 8,92 | 14,35 |
| HTTP Backend → ML → Backend | 15,21 | 22,77 |
| Подготовка признаков | 42,26 | 65,02 |
| Цикл Backend | 95,75 | 149,46 |
| Приём события → публикация прогноза | 172,32 | 316,50 |

Последняя строка включает ожидание такта Backend, но не доставку от устройства
и не отрисовку UI. Дашборд опрашивает API раз в секунду.

В [снимке состояния](performance-v5-sample.json) записаны 29 532 кадра, 30 подключений,
8 закрытий соединений, ноль ошибок CRC и повреждённых кадров. Проверено
восстановление после разрыва TCP и остановки/запуска ML. Это демонстрационный
прогон; частота входящих кадров, характеристики CPU и RAM хоста не зафиксированы.

## Воспроизводимость запуска

27.09.2026 проверен отдельный чистый клон v5 на macOS arm64, Docker Engine 29.5.2,
Linux aarch64: три healthy-сервиса без `.env` и изменений Dockerfile.
Использовался кеш образов. В NDTP-проверке принято 6707 кадров без ошибок
CRC, некорректных и обрезанных кадров; прогнозы попадали в горизонт `(600, 900]`.
[Протокол](delivery-29-verification.json).

Это проверка запуска, а не холодного старта без кеша. Предельная пропускная
способность, многочасовая нагрузка и задержка до браузера отдельно не измерялись.
