# Инструкция для жюри

Все команды выполняются из корня проекта. Нужен Docker с Compose v2;
модель и исторические данные входят в репозиторий.

## 1. Запустите систему

```bash
docker compose up -d --build --wait
```

Откройте **http://localhost:8080**. Команда ждёт готовности ML, Backend и дашборда.
Тестовый ключ Яндекс Карт включён в поставку и подхватывается при сборке.
Создавать `.env` перед запуском не нужно. Для загрузки карты нужен интернет.

## 2. Посмотрите прогнозы и алерты

Исторический replay включён по умолчанию: данные `dataset/test/traffic.csv`
подаются с 08:00 на скорости 60×.

1. В очереди **«Требуют внимания»** выберите транспортное средство.
2. В карточке проверьте прогноз задержки, плановое прибытие и горизонт 10–15 минут.
   Положительная задержка означает опоздание, отрицательная означает опережение.
3. Откройте **«Из чего сложился прогноз»**, сценарий выпуска резервного ТС
   и паспорт предупреждения. Алерт можно отметить как **«Принято в работу»**.
4. На карте видны положение ТС, пройденный трек и схема следующих остановок.
5. В панели **«Система»** посмотрите качество прогнозов, задержки расчёта,
   счётчики пакетов и свежесть данных.

Внизу доступны пауза, скорость и выбор времени. На телефоне используйте вкладки
«Очередь / Карта / ТС / Система».

## 3. Подайте NDTP-поток

### Исторические данные через TCP

Нажмите **«CSV replay»** внизу экрана
и выбрать **«Наш NDTP-replayer»** в панели источников. Он кодирует CSV-телеметрию
в бинарные кадры NDTP и отправляет их в Backend.

Для запуска из терминала вместо панели:

```bash
BACKEND_MODE=ndtp BACKEND_DEMO_ENABLED=false docker compose up -d --wait backend
docker compose --profile tools run --rm ndtp-replay
```

Отправитель воспроизводит интервал 08:00–10:00 на скорости 60×.
Backend слушает TCP-порт **9201**. Проверка счётчиков:

```bash
curl -s http://localhost:8010/api/v1/status | python3 -m json.tool
```

В блоке `ndtp` растут `handshakes` и `realtime_frames`; в штатном потоке
`crc_errors` и `invalid_frames` равны нулю. Прогноз появится, когда накопится
история и в горизонте 10–15 минут будет плановая остановка.

### Официальный эмулятор

Образ нужно импортировать отдельно из [раздачи организаторов](https://disk.yandex.ru/d/CA6tsj4aJJ4Aaw):

```bash
docker load -i /путь/к/ndtp-telemetry-emulator.tar
docker compose --profile emulator up -d emulator
```

Если раздача содержит распакованный OCI-каталог вместо tar:

```bash
tar -C dataset/ndtp-telemetry-emulator -cf /tmp/ndtp-emulator.tar .
docker load -i /tmp/ndtp-emulator.tar
docker compose --profile emulator up -d emulator
```

Восстановите управление через панель, если до этого использовали ручной запуск:

```bash
docker compose up -d --wait backend
```

В панели источников выберите **«Эмулятор организаторов»**: панель настроит
адрес и устройства. Не запускайте другого отправителя параллельно.
Эмулятор двигает ТС случайно: он проверяет приём протокола, а не точность модели.

### Внешний отправитель

```bash
BACKEND_MODE=ndtp BACKEND_DEMO_ENABLED=false docker compose up -d --build --wait
```

Подключите клиент к `<адрес машины>:9201`. Формат пакетов описан в
[спецификации NDTP](../dataset/docs/Emulator-and-Telematic-Packets-Specification.md).
Используйте `unit_id` из датасета: для неизвестного устройства нет привязки к расписанию.
По умолчанию Backend сдвигает дату плана на целые сутки к дате первого известного
устройства; применённый сдвиг виден в `status.plan.shift_s`.
Часовой пояс CSV не задан, автоматической коррекции времени суток нет.

В NDTP-режиме можно смотреть прошлые снимки на шкале времени и вернуться кнопкой
**«К потоку»**. Приём пакетов продолжается. История хранится в памяти текущего
прогона; смена источника или перезапуск её очищает.

## 4. Откройте метрики и API

| Адрес | Содержание |
|---|---|
| http://localhost:8080/docs | Swagger Backend |
| http://localhost:8011/docs | Swagger ML |
| http://localhost:8010/api/v1/metrics/quality | Качество и итоги предупреждений |
| http://localhost:8010/api/v1/metrics | Время расчёта и счётчики |
| http://localhost:8010/api/v1/status | Состояние потока, модель и ошибки |
| http://localhost:8011/v1/model | Версия модели и фактический движок инференса |

Compose запрашивает ONNX Runtime; при неудачной стартовой проверке используется
CatBoost. Поля `runtime` и `runtime_note` показывают выбранный вариант.

MAE исторического replay на test не является независимой оценкой: эти данные
участвовали в обучении v8. Паспорт предупреждения определяет прибытие по GPS,
поэтому его результат зависит от точности и полноты телеметрии.

## 5. Проверьте восстановление

```bash
docker compose stop ml      # Backend продолжает отвечать, UI показывает недоступность ML
docker compose start ml     # расчёт возобновляется после готовности модели
```

Чтобы вернуться к исходному CSV replay после ручных сценариев, выполните
`docker compose up -d --wait backend` с исходным `.env`.
Остановка стенда: `docker compose --profile tools --profile emulator down`.
