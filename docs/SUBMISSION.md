## 5. Производительность и дополнительные возможности

```
Производительность (Docker, поток NDTP, модель v5; <REPO>/docs/PERFORMANCE.md):
инференс ML p50/p95 8,9/14,4 мс; Backend→ML→Backend 15,2/22,8 мс; событие→прогноз
172/317 мс (с ожиданием такта 0,5 с); цикл 96 мс при такте 500 мс — очереди не копятся.
Память: Backend 137→139 МиБ за 30 мин потока (без роста), ML 85 МиБ, UI 5 МиБ.
Холодный старт из чистого клона — 3 сервиса healthy за 1 мин 38 с. NDTP: 56 тыс. кадров,
0 ошибок CRC, 8 обрывов с переподключением. Отказ ML: сервис жив, последний прогноз
с возрастом, восстановление без перезапуска.

Дополнительные возможности (<REPO>/docs/FEATURES.md):
- What-if «выпуск резервного ТС»: рейсы линии без/с резервом, сколько опозданий избегаем.
- Ансамбли CatBoost (3+3) с маршрутизацией по наличию подсказки; вероятность опоздания
  с калибровкой, проверенной вне фолдов (Brier 0,107; без подсказки 0,116). Ансамбль с
  нейросетью PyTorch (GRU по телеметрии) проверен тем же протоколом и не включён: не улучшил.
- Map matching по плану с фильтром подмены GNSS (фиксы у Шереметьево скрыты с карты).
- Оптимизация инференса: ONNX Runtime с проверкой паритета (≤ 8e-05 с), ×4,8 быстрее
  CatBoost на одиночном запросе (1,8 мс p50); объяснения SHAP — по запросу.
- Паспорт предупреждения: первое предупреждение → факт по GPS, доля подтверждённых,
  упреждение (медиана ≈11 мин до фактического прибытия).
- Объяснение прогноза (вклады групп признаков в секундах), «где копится опоздание»,
  приоритет первого/последнего рейса, конкретные рекомендации, «принято в работу».
- Мобильный вид (вкладки, установка на телефон как PWA) и опциональный вход с ролями
  диспетчер/наблюдатель (имя в отметке «принято в работу»; по умолчанию выключен).
```
